# End-to-end orchestration test

`run_scenario.py` drives the **real** deterministic scripts (`validate_envelope`,
`consolidate`, `verify`, `judge`, `frontier`) through the full loop and every handoff —
fan-out → validate → consolidate → adversarial-verify → judge → frontier-expand →
loop/stop — using scripted agent envelopes as stand-ins for live sub-agents. Agents are
simulated (not live LLMs) so the test is deterministic and repeatable in CI.

## Run

```bash
python3 skills/multi-agent-orchestrator/tests/run_scenario.py        # check; exit 0/1
python3 skills/multi-agent-orchestrator/tests/run_scenario.py --emit # print actual final JSON + sha256
```

## Two scenarios

- **A — happy recursion**: fan-out; a malformed/uncitable envelope is rejected at the gate;
  findings merge with confidence floored; a conflict is preserved; adversarial skeptics
  refute one finding (removed) and confirm another (kept); recursion follows a residual lead
  into wave 2, dries up, and stops `saturated`; coverage reconciles to `complete`.
- **B — blocked / partial**: a blocked agent forces `partial` coverage; the frontier dries
  with the judge unsatisfied, so the run stops `frontier_exhausted` and records the unmet
  quality bar in `residual_uncertainty` (the loop never invents leads).
- **C — spawn gate**: identical to A through wave 1, but wave 2 is not human-approved. Agents
  cannot self-spawn, so the run halts `awaiting_human_approval`, surfaces the manager's
  recommendation (proposed scopes), and never dispatches wave 2 — no wave-2 finding appears.

## How to validate the test independent of the answer

Three independent mechanisms, so you don't have to trust the run:

1. **Structured oracle** — `fixtures/oracle.json` states the expected final state and the
   reasoning behind it. It was authored **by hand from the fixtures**, not generated by the
   pipeline. Read `scenario_a.json` / `scenario_b.json` and confirm each oracle value
   yourself, then confirm `run_scenario.py` reproduces it.
2. **Property invariants (P1–P8)** — checks that must hold for *any* correct run regardless
   of the specific answer: citable provenance only, no refuted key survives, no fabrication,
   conflicts preserved as ≥2 variants, `complete` never with a block, determinism. Listed in
   `oracle.json._property_invariants` and enforced in `_check_properties`.
3. **Pinned sha256** — `oracle.json` pins the hash of each scenario's final consolidated
   JSON. Any change in behavior changes the hash; reproducing the pin proves byte-for-byte
   identity.

## Prove it has teeth (negative control)

Flip a skeptic vote so the refuted finding would survive, and the test fails — showing the
oracle actually constrains the outcome:

```bash
cp -r skills/multi-agent-orchestrator/tests /tmp/t && \
sed -i 's/"REL": {"refuting": 3, "confirming": 1/"REL": {"refuting": 1, "confirming": 3/' /tmp/t/fixtures/scenario_a.json && \
python3 /tmp/t/run_scenario.py   # -> FAIL (REL survives; P2 + oracle + hash all break)
```
