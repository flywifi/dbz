# MAINTAINER — permission-aware-connector-template

## Purpose
`SKILL.md` is the runtime contract; this file preserves non-negotiable behavior for
`permission-aware-connector-template` so a future maintainer keeps the intended scope.

## Non-negotiable invariants
- Access mode determined by `references/access-modes.md` — never assume OAuth/API keys exist.
- Permission matrix must be generated by `scripts/generate_permission_matrix.py`, not hand-written.
- Scope coverage must be validated by `scripts/validate_scope.py` before the template is considered complete.
- Least-privilege principle: never grant broader permissions than the resource model requires.
- No real credentials, tokens, or secrets in any template output — placeholders only.
- `human_review_required: true` on any permission model output — an operator must review before deployment.

## Known failure modes
- **Auth stack hand-waving**: generating a template that assumes an auth stack exists ("configure your OAuth provider here") without a concrete no-OAuth fallback path. Always provide both.
- **Overly-broad scope grants**: generating `read:all` or wildcard scopes when the resource model only needs one endpoint. Always enumerate the minimum required scopes.
- **Credential leakage**: including example API keys, client secrets, or real tokens in template output. Use clearly labeled placeholders: `<YOUR_CLIENT_ID>`, `<YOUR_CLIENT_SECRET>`.
- **Missing operator review gate**: treating the permission matrix as "ready to deploy" without flagging that operator review is required.

## Fragile fallbacks that must not become defaults
- No-OAuth templates must still enforce resource access controls (API key scoping, IP allowlisting) — "no OAuth" does not mean "no auth."
- `access-mode.json` must always be written; the chosen access mode cannot be inferred by downstream tools.

## Regression cases to preserve
1. Returns `human_review_required: true` in every permission model output.
2. Permission matrix contains no real credentials — only placeholders.
3. Both a no-OAuth path and a full-OAuth path are always documented.
4. `validate_scope.py` reports coverage before the template is finalized.
5. Does not generate wildcard scopes when enumerable resource-specific scopes exist.

## Approval-gated changes
- Adding new permission model types (e.g., ABAC, RBAC variants).
- Changing the minimum-scope derivation logic in `generate_permission_matrix.py`.
- Modifying the template output schema.
- Adding new auth stack integrations.

## Minority-report policy
When two security models (e.g., OAuth PKCE vs. API-key-scoped) are both valid for the same
resource and carry different risk trade-offs, emit `minority_report.failed_to_merge` with both
models rather than silently choosing one. The operator decides.
See canonical policy: `skills/shared/minority-report.md`.

## Update checklist (every version bump)
- [ ] Confirm `references/access-modes.md` access-mode hierarchy is current.
- [ ] Run `scripts/validate_scope.py` against smoke-test template — must report 100% coverage.
- [ ] Confirm no real credentials in any template output path.
- [ ] Confirm `human_review_required: true` present in all permission model output paths.
- [ ] Verify no-OAuth fallback path is still documented alongside full-auth path.
## Confirmation-sync & durable logging
Uncertainties this skill emits (conflicts, partials, inferred edges, ODP clashes, agent
dissent) carry a deterministic `uncertainty_id`, log the competing citations plus
`why_conflict` / `winning_citation` / `why_it_won`, and are recorded in
`canonical-sources/uncertainty_ledger.jsonl`. Human confirmations live in
`canonical-sources/confirmations.jsonl`; on confirm, `status`, `needs_confirmation`,
`confidence`, and any partial->full reclassification re-derive at build. Never resolve an
uncertainty in place — only via the confirmations ledger. See `skills/shared/minority-report.md`.
